# BikeMB 项目说明

## 项目目标

BikeMB 是一个用于 AI 学习和嵌入式实践的 ESP32 自行车码表项目，使用 1.8 寸圆形屏幕展示骑行状态。产品形态参考现代 e-bike 中控和码表系统，但第一阶段只实现基础骑行数据显示，不控制电机、不接入车辆动力系统。

## 第一阶段定位

第一阶段做一个可以真实安装在自行车上测试的基础码表。

核心价值：

- 骑行时一眼看清速度、里程、时间和电量。
- 使用简单传感器完成真实数据采集。
- 项目结构适合继续扩展 GPS、BLE、导航、心率和数据记录。
- 适合作为 vibe-coding 学习项目，每一步都能烧录验证。

## 建议技术方向

默认建议：

- 主控：ESP32 系列开发板
- 屏幕：1.8 寸圆形 TFT/OLED 屏幕
- 框架：Arduino 或 PlatformIO + Arduino
- UI：LVGL + TFT_eSPI 或 LovyanGFX
- 速度：第一阶段优先使用霍尔传感器 + 轮圈磁铁
- 存储：ESP32 NVS/Preferences
- 交互：至少一个实体按键

待确认项：

- 具体 ESP32 型号
- 屏幕分辨率
- 屏幕驱动芯片
- 是否带触摸
- 是否电池供电
- 电池电压采样电路
- 霍尔传感器型号和接线引脚

## 范围内

- 圆屏骑行主界面
- 实时速度计算
- 单次里程
- 骑行时间
- 总里程保存
- 设备电量显示
- 基础设置
- 按键页面切换
- 基础低电量提示

## 暂不包含

- 电助力电机控制
- 刹车、扭矩、踏频闭环控制
- 云同步
- 手机 App
- 复杂地图导航
- OTA 升级
- 多车管理

这些能力可以作为第二阶段或第三阶段变更加入。

## 需求书写约定

- 用 `REQ-` 表示功能需求。
- 用 `NFR-` 表示非功能需求。
- 每个需求应尽量能被测试或观察。
- 新功能先进入 `openspec/changes/`，确认后再落入 `openspec/specs/`。

## 协作方式

推荐每次开发都按这个顺序进行：

1. 修改或新增 OpenSpec 变更。
2. 确认任务清单。
3. Codex 实现一个小步。
4. 烧录或本地验证。
5. 记录问题，再进入下一步。
