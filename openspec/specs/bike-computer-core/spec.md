# bike-computer-core 规格

## 目标

定义 BikeMB 第一阶段的基础码表能力。后续实现应以此为准。

## Requirements

### REQ-001 实时速度显示

系统应显示当前骑行速度。

#### Scenarios

- Given 轮速传感器产生连续脉冲
- When 系统收到脉冲并完成计算
- Then 主界面应显示当前速度

- Given 车辆停止且超过速度归零阈值
- When 系统没有收到新的轮速脉冲
- Then 当前速度应回落为 `0`

### REQ-002 单次骑行里程

系统应累积本次骑行里程。

#### Scenarios

- Given 已配置轮径参数
- When 轮速传感器记录到一个有效轮转
- Then 单次里程应增加一个轮周长对应的距离

### REQ-003 骑行时间

系统应记录当前骑行用时。

#### Scenarios

- Given 系统处于骑行状态
- When 时间经过 `1` 秒
- Then 骑行时间应增加 `1` 秒

- Given 系统处于暂停状态
- When 时间经过 `1` 秒
- Then 骑行时间不应增加

### REQ-004 总里程保存

系统应持久化设备总里程，断电后不丢失。

#### Scenarios

- Given 当前总里程为 `100.0 km`
- When 本次骑行新增 `1.2 km` 并结束
- Then 下次开机后总里程应显示为 `101.2 km`

### REQ-005 电量显示

系统应显示设备自身电池电量。

#### Scenarios

- Given 设备通过电池供电
- When 系统读取电池电压
- Then UI 应显示估算电量百分比或电池图标

### REQ-006 圆屏主界面

系统应提供适合圆形屏幕的主骑行界面。

#### Scenarios

- Given 用户正在骑行
- When 用户查看屏幕
- Then 当前速度应作为最大视觉元素显示

- Given 用户查看主界面
- When 屏幕正常刷新
- Then 应同时看到速度、单次里程、骑行时间和电量状态

### REQ-007 按键切换页面

系统应支持至少一个实体按键切换页面。

#### Scenarios

- Given 当前显示主界面
- When 用户短按按键
- Then 系统应切换到下一个页面

### REQ-008 基础设置

系统应提供基础设置能力。

#### Scenarios

- Given 用户进入设置页面
- When 用户调整轮径、单位或亮度
- Then 系统应保存设置并在下次启动时继续使用

## Non-Functional Requirements

### NFR-001 可读性

主界面的速度数字应足够大，适合骑行中快速辨认。

### NFR-002 启动时间

第一阶段目标是在上电后 `3` 秒内看到主界面。

### NFR-003 刷新稳定性

UI 刷新应平稳，不应阻塞关键数据采集。

### NFR-004 Flash 写入控制

总里程和设置数据应避免高频写入 Flash。

### NFR-005 可扩展性

代码结构应预留后续接入 `GPS`、`BLE`、心率和轨迹记录的空间。
