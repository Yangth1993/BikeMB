BikeMB LVGL UI Architecture

当前 UI 以 LVGL 原生控件实现。设计稿不能直接“转换”为 LVGL 代码，实际流程是把视觉拆成页面、控件、样式、数据绑定和交互事件，再逐项映射到 LVGL 对象。

当前分层

Runtime

bike_runtime 负责事件队列和任务启动。后续真实传感器数据应从这里进入服务层。

Services

metrics_service 提供当前 dashboard 数据。现在仍是 demo 数据，后续替换为真实速度、电量和里程。

App / View

dashboard_view_core 管页面生命周期和切页，dashboard_pages 管三页布局和动态文本。

Platform / Drivers

lvgl_port 注册显示和触摸输入，驱动层处理 LCD、I2C、EXIO 和 CST816。

数据流

Demo / Sensor

速度、功率、电量、里程

Metrics Service

生成 DemoMetrics

Dashboard App

按固定帧率更新视图

Dashboard Pages

更新 label、波形和状态

LVGL Port

flush 到 ST77916，读取 CST816

设计稿到 LVGL 的映射

设计元素LVGL 实现注意事项
圆形屏背景lv_obj + 圆角/边框圆屏上要保留安全边距，不能把可读文本贴到边缘。
大速度数字lv_label 固定宽度居中必须按最大位数预留，例如 99.9 或 100。
模式按钮lv_obj panel + LV_EVENT_CLICKED点击只做 UI 测试，正式模式状态应进入服务层。
波形图lv_line + 手绘 grid当前是轻量实现；若需要坐标轴/填充，可换 lv_chart 或 canvas。
详情列表重复 row panel + 固定宽度 label数值和单位建议拆开，避免长单位挤爆。

Figma / Stitch 是否可用

可以用但它们不是 LVGL 代码生成器。推荐把 Figma 或 Stitch 当作视觉定稿工具，导出尺寸、颜色、字体层级、图标和页面状态；实现时仍需要在 LVGL 中手工搭控件树。

最可靠的交付格式是：360x360 PNG 预览、颜色 token、字号表、控件坐标/边距、图标 SVG/PNG、每个页面的状态说明。不要依赖自动生成代码直接进固件。
