# BikeMB 产品需求

## 范围说明

本文件描述产品层需求。正式行为规格以 `openspec/specs/` 和已接受的 `openspec/changes/` 为准。

## 优先级定义

- P0：第一阶段基础码表必须具备。
- P1：第一阶段可延后，但会明显提升可用性或可验证性。
- P2：后续实验或扩展方向，不能影响 P0。

## P0 需求

### REQ-P0-001 主界面显示当前速度

用户骑行时，主界面必须以最大视觉元素显示当前速度。

验收标准：

- 给定系统收到有效轮速数据，主界面显示当前速度。
- 给定车辆停止且超过归零阈值，当前速度回落为 0。
- 速度数字在 360 x 360 圆形屏上可快速辨认。

### REQ-P0-002 单次里程

系统必须累计本次骑行里程。

验收标准：

- 给定已配置轮径参数，收到一次有效轮转后，单次里程增加对应轮周长。
- 主界面或信息页能查看本次里程。

### REQ-P0-003 骑行时间

系统必须记录当前骑行用时。

验收标准：

- 骑行状态下，每经过 1 秒，骑行时间增加 1 秒。
- 暂停状态下，骑行时间不增加。
- 用户能在界面上查看骑行时间。

### REQ-P0-004 电量显示

系统必须显示设备自身电池电量状态。

验收标准：

- 设备通过电池供电时，系统读取电池电压。
- UI 显示估算电量百分比或电池图标。
- 电量显示异常不应阻塞速度和里程显示。

### REQ-P0-005 总里程保存

系统必须持久化总里程。

验收标准：

- 本次骑行新增里程结束后，总里程被更新。
- 断电重启后，总里程不丢失。
- 实现应避免高频 Flash 写入。

### REQ-P0-006 页面切换

系统必须支持至少一个实体按键切换页面。

验收标准：

- 当前在主界面时，短按按键切换到下一页。
- 页面切换不应阻塞核心数据刷新。

### REQ-P0-007 启动可用

设备必须能在可接受时间内进入可用状态。

验收标准：

- 上电后 3 秒内显示主界面。
- 启动失败或外设异常时，应优先保留串口日志用于定位。

## P1 需求

### REQ-P1-001 基础设置

系统应支持设置轮径、单位和亮度。

验收标准：

- 用户可进入设置页面调整轮径、单位或亮度。
- 设置保存后，下次启动继续使用。

### REQ-P1-002 LVGL 正式 UI 基线

正式工程应使用 LVGL 作为 UI 绘制层。

验收标准：

- `src/firmware/bikemb` 能运行 LVGL dashboard。
- UI 层与数据、输入、存储等模块保持清晰边界。
- bring-up 工程继续保留为硬件验证入口。

### REQ-P1-003 数据链路可替换

第一阶段可先用 demo 数据，但必须能逐步替换为真实传感器数据。

验收标准：

- UI 不直接依赖固定 demo 常量。
- 后续接入轮速、电池和设置数据时，不需要重写主界面结构。

## P2 需求

### REQ-P2-001 音频自检

系统可提供默认关闭的音频自检，用于验证麦克风和扬声器链路。

验收标准：

- 功能由编译开关控制，默认关闭。
- 自检不改变核心码表默认行为。

### REQ-P2-002 模式语音提示

系统可提供默认关闭的本地预录音模式提示。

验收标准：

- 功能由编译开关控制，默认关闭。
- 不引入云 TTS 或实时 TTS 依赖。

### REQ-P2-003 语音页面命令

系统可实验默认关闭的语音上一页/下一页命令。

验收标准：

- 功能由编译开关控制，默认关闭。
- 第一版仅作为识别验证，不提供完整语音助手。
- 误触发风险必须在文档和测试中明确。

### REQ-P2-004 云 AI 音箱模式

系统可在未来探索云 AI 音箱和云音乐播放。

验收标准：

- 不影响 BikeMB 作为自行车码表的主定位。
- 核心骑行显示不依赖云服务。
- Wi-Fi、AI 服务、语音转换或播放失败时，不阻塞速度、电量和页面切换。
- 仓库中不得提交 API token、Wi-Fi 密码或个人数据。

## 第一阶段排除项

- 电机控制
- 手机 App
- 云同步
- 复杂导航
- OTA
- 轨迹记录
- 心率
- 完整离线语音助手
