# BikeMB 用户故事

## 用户角色

### 骑行者

在骑行中查看基础骑行信息，操作应尽量少，信息应快速可读。

### 项目开发者

在真实板卡上持续验证硬件、UI、数据链路和扩展功能，要求每一步都能稳定回退到可用状态。

## P0 用户故事

### US-P0-001 查看当前速度

作为骑行者，我想在主界面一眼看清当前速度，以便骑行中快速判断状态。

验收标准：

- 主界面速度是最大视觉元素。
- 收到有效轮速数据后，速度显示更新。
- 停止骑行超过归零阈值后，速度显示为 0。

### US-P0-002 查看本次骑行进度

作为骑行者，我想查看本次里程和骑行时间，以便了解本次骑行进展。

验收标准：

- 界面显示本次里程。
- 界面显示骑行时间。
- 暂停状态不累计骑行时间。

### US-P0-003 查看设备电量

作为骑行者，我想查看设备电量，以便判断是否需要充电。

验收标准：

- UI 显示电量百分比或电池图标。
- 电量显示不遮挡速度、里程和时间。

### US-P0-004 切换页面

作为骑行者，我想通过实体按键切换页面，以便骑行中不依赖复杂触摸操作。

验收标准：

- 短按实体按键切换到下一页。
- 页面切换后核心数据仍继续刷新。

### US-P0-005 保留总里程

作为骑行者，我想设备断电后仍保留总里程，以便长期累计使用。

验收标准：

- 骑行结束后总里程更新。
- 断电重启后总里程恢复。

## P1 用户故事

### US-P1-001 调整基础设置

作为骑行者，我想设置轮径、单位和亮度，以便设备适配我的自行车和使用环境。

验收标准：

- 可以进入设置页面。
- 可以保存轮径、单位和亮度。
- 重启后设置仍生效。

### US-P1-002 验证正式 UI 基线

作为项目开发者，我想在 `src/firmware/bikemb` 中运行 LVGL dashboard，以便后续功能基于正式 UI 层迭代。

验收标准：

- `src/firmware/bikemb` 能显示 dashboard。
- dashboard 信息结构接近已验证 bring-up dashboard。
- `src/firmware/bringup` 仍保留为硬件验证入口。

### US-P1-003 替换真实数据

作为项目开发者，我想把 demo 数据逐步替换为真实传感器数据，以便从 UI demo 过渡到可骑行产品。

验收标准：

- UI 层不需要因单个数据源替换而重写。
- 真实速度、电量和持久化数据可以分阶段接入。

## P2 用户故事

### US-P2-001 音频链路自检

作为项目开发者，我想用默认关闭的音频自检验证麦克风和扬声器，以便在做语音能力前确认硬件链路。

验收标准：

- 自检由编译开关启用。
- 默认固件不播放自检音频。
- 自检不影响核心 dashboard。

### US-P2-002 模式语音提示

作为骑行者，我想在切换模式时听到本地语音提示，以便不看屏幕也能确认模式变化。

验收标准：

- 功能默认关闭。
- 使用本地预录音频，不依赖云 TTS。
- 播放失败不影响模式状态和页面显示。

### US-P2-003 语音翻页实验

作为项目开发者，我想验证简单语音上一页/下一页命令，以便评估语音交互是否适合 BikeMB。

验收标准：

- 功能默认关闭。
- 第一版只识别页面命令。
- 误触发风险不影响默认固件。

### US-P2-004 云 AI 音箱实验

作为项目开发者，我想探索设备直连云 AI 和云音乐，以便评估 BikeMB 的娱乐和语音扩展空间。

验收标准：

- 该能力不改变 BikeMB 的码表主定位。
- 录音必须由实体按键或触摸主动触发。
- 网络或服务失败不影响核心骑行显示。
- 密钥、密码和个人数据不得进入仓库。
