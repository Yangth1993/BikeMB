# BikeMB AI 助手方案

## 方案定位

BikeMB AI 助手 V1 先做 AI 音箱能力，再逐步扩展为骑行助手和设备助手。

V1 的目标是验证设备直连 Wi-Fi、云端 AI 问答、语音回复和云音频流播放闭环。它是 P2 实验能力，默认不应影响核心码表功能。速度、电量、里程、页面切换等本地码表能力必须在 AI 服务不可用时继续工作。

## V1 产品目标

- 用户按住实体按键说话，松开后设备处理语音请求。
- 设备通过云端 STT 将语音转成文字。
- 设备将文字问题发送给 DeepSeek。
- DeepSeek 返回文本回答。
- 设备通过云端 TTS 将回答转成语音并播放。
- 设备支持播放预设云音频流或用户配置的音频流 URL。
- 语音处理和音乐连接过程中，屏幕必须提示用户等待。

## V1 非目标

- 不做唤醒词。
- 不做语音点歌。
- 不做手机或电脑代理。
- 不做自建中转服务。
- 不做完整骑行助手。
- 不做完整设备控制助手。
- 不让云 AI 成为核心码表功能依赖。

## 用户流程

### 语音问答

1. 用户按住实体 AI 按键。
2. 屏幕显示 `正在聆听`。
3. 用户说出问题。
4. 用户松开按键。
5. 屏幕显示 `正在识别`。
6. STT 服务将语音转成文字。
7. 屏幕显示 `正在思考`。
8. DeepSeek 生成回答文本。
9. 屏幕显示 `正在准备语音`。
10. TTS 服务生成语音。
11. 设备播放回答。
12. 屏幕回到 AI 空闲状态或码表主界面。

### 音乐播放

1. 用户通过 AI 入口或后续设置选择播放音乐。
2. 系统选择默认预设音频流或用户配置 URL。
3. 屏幕显示 `正在连接音乐`。
4. 音频流连接成功后开始播放。
5. 屏幕显示 `音乐播放中`。
6. 用户可停止播放。

## 交互状态

| 状态 | 屏幕提示 | 说明 |
| --- | --- | --- |
| Idle | `AI 待命` | AI 功能可用，等待用户按住按键 |
| Recording | `正在聆听` | 用户按住实体键时录音 |
| Recognizing | `正在识别` | 录音结束，等待 STT 结果 |
| Thinking | `正在思考` | 已得到文字问题，等待 DeepSeek 结果 |
| Synthesizing | `正在准备语音` | 等待 TTS 生成回答音频 |
| Speaking | `正在回答` | 播放 AI 语音回答 |
| ConnectingMusic | `正在连接音乐` | 建立云音频流 |
| MusicPlaying | `音乐播放中` | 音乐或音频流正在播放 |
| Error | `AI 暂时不可用` | 网络、服务、音频或超时失败 |

屏幕等待提示应保持轻量，不遮挡核心码表的关键安全信息。若当前处于码表主界面，可以使用小状态条、顶部图标或底部提示区显示 AI 状态。

## 功能列表和优先级

### P2-AI-001 按住说话

用户按住实体 AI 按键开始录音，松开结束录音。

验收标准：

- 按下按键后进入录音状态。
- 松开按键后停止录音并进入识别状态。
- 录音期间屏幕显示 `正在聆听`。
- 录音最大时长应有上限，避免异常长录音。

### P2-AI-002 DeepSeek 问答

系统使用 DeepSeek 作为 V1 默认大模型服务。

验收标准：

- STT 输出文字后，系统将问题发送给 DeepSeek。
- DeepSeek 返回文本回答后进入 TTS 阶段。
- DeepSeek API key 不得进入仓库。
- DeepSeek 作为默认服务，但接口设计应保留替换空间。

### P2-AI-003 独立 STT/TTS

系统使用独立 STT/TTS 服务完成语音输入和语音输出。

验收标准：

- STT 负责把用户语音转成文字。
- TTS 负责把 DeepSeek 回答转成语音。
- STT/TTS 服务商可替换。
- STT/TTS 密钥不得进入仓库。

### P2-AI-004 云音频流播放

系统支持播放预设云音频流和用户配置音频流 URL。

验收标准：

- V1 至少支持一个预设音频流。
- V1 支持从配置中读取用户音频流 URL。
- 不支持语音点歌。
- 音频流失败时不影响核心码表。

### P2-AI-005 等待状态提示

AI 处理期间，屏幕必须向用户提示当前等待状态。

验收标准：

- 录音时显示 `正在聆听`。
- STT 阶段显示 `正在识别`。
- DeepSeek 阶段显示 `正在思考`。
- TTS 阶段显示 `正在准备语音`。
- 音乐连接阶段显示 `正在连接音乐`。
- 出错或超时时显示 `AI 暂时不可用`。

### P2-AI-006 取消和失败恢复

AI 问答、语音播放和音乐播放应可取消，并能从失败中恢复。

验收标准：

- 用户可中断录音、语音回答或音乐播放。
- AI 失败后返回 AI 空闲状态或码表主界面。
- AI 失败不阻塞速度、电量、里程和页面切换。

## 延迟目标

V1 接受云端串联带来的延迟，但必须给用户明确等待反馈。

验收标准：

- 短语音问题在松开按键后，目标为 8 秒内开始语音回复。
- 超过 15 秒无结果，应进入失败状态并允许重试。
- 音乐播放请求应在 10 秒内开始播放或明确失败。
- 所有等待阶段都应显示屏幕提示。

## 云服务策略

V1 默认服务组合：

- 大模型：DeepSeek
- 语音转文字：独立 STT 服务
- 文字转语音：独立 TTS 服务
- 音乐播放：预设音频流或用户配置 URL

产品要求：

- DeepSeek 不是免费假设，V1 需要 API key 和预算边界。
- 所有云服务密钥、Wi-Fi 密码和个人信息不得提交到仓库。
- 默认服务商可以被替换，产品方案不绑定长期唯一供应商。

## 安全和隐私边界

- V1 不做常开监听。
- 只有用户按住实体按键时才录音。
- 松开按键后停止录音。
- 录音、转写文本、AI 回答和音频播放不得写入 Git 跟踪文件。
- 网络失败、服务失败或超时不能影响本地码表能力。

## 后续路线

### V2 骑行助手

在 AI 音箱闭环稳定后，加入骑行上下文：

- 当前速度
- 本次里程
- 骑行时间
- 电量状态
- 简单骑行状态播报

V2 仍应避免 AI 改写核心骑行数据，AI 只能读取受控摘要。

### V3 设备助手

在骑行助手稳定后，加入有限设备控制：

- 翻页
- 亮度调整
- 模式切换
- 状态播报
- 简单故障诊断

设备助手必须经过命令白名单，不允许 AI 直接调用任意固件接口。

## 待确认问题

- V1 使用哪个 STT 服务。
- V1 使用哪个 TTS 服务。
- 用户配置音频流 URL 的来源：编译配置、串口配置、设置页或本地配置文件。
- AI 按键是否复用现有实体键，还是需要定义独立按键。
- AI 状态提示在圆屏 UI 中放在顶部、底部还是独立 AI 页面。
