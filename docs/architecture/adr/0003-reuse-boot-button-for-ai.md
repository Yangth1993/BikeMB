# ADR-0003: 复用 BOOT 键作为 AI 按键

## 状态

Accepted

## 背景

Waveshare ESP32-S3-Touch-LCD-1.85C V2 的板载 `Key1` 连接 `GPIO0`，低电平有效，并由 `R27 10 kΩ` 上拉到 3.3 V；`Key2` 连接复位。产品希望不增加外接按键，在应用运行后复用 BOOT 键完成按住说话。

GPIO0 同时是 ESP32-S3 的启动 strap。芯片会在复位阶段采样该引脚；按住 BOOT 上电或复位会进入 ROM 下载模式。应用固件中的延时无法改变复位前的采样结果。

## 决策

- V1 使用板载 `Key1/BOOT (GPIO0)` 作为 AI 实体键，不使用 `Key2/RESET`。
- 按键低电平有效，使用板载 `10 kΩ` 上拉；固件不得配置下拉。
- 上电后的前 `3000 ms` 不产生 AI 按键事件。
- `3000 ms` 保护期结束后，只有检测到连续 `50 ms` 高电平释放状态才进入 Armed；若按键从上电持续按住，松开并稳定后才可接受下一次按下。
- Armed 后使用 `30 ms` 消抖，并分别产生一次 `PRESS` 和一次 `RELEASE`。
- 固件和 UI 不宣称该延时能禁用下载模式；按住 BOOT 上电或复位仍会进入 ROM 下载模式。

## 后果

- 无需外接按键或修改 PCB，V1 可直接验证按住说话。
- 正常上电后的前 3 秒不能启动 AI 录音。
- 用户在按住 AI 键时触发上电、复位或看门狗复位，设备可能停留在 ROM 下载模式，必须松开按键并再次复位。
- 上板验证必须覆盖正常启动、保护期误按、持续按住跨越保护期、运行态短按/长按，以及按住 BOOT 复位后的恢复说明。
