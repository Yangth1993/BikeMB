当前运行路径

工程同时保留 Arduino 验证路径和 ESP-IDF 迁移路径。当前 UI、触摸、语音输出、语音识别和 AI 控制框架都以 Arduino 环境为主。

默认路径：Arduino

入口在 main.cpp 的 setup() / loop()。dashboard、触摸滑动、档位播报、音频自检、直接语音识别以及默认关闭的 AI framework 都走这里。

迁移路径：ESP-IDF

入口在 main.cpp 的 app_main()。目前已有 Runtime/Event/Service 骨架，但 AI、音频和语音尚未接入这条运行路径。

取消与旧结果隔离

取消或忙态重新按键会递增有效 requestId，旧 callback 不能改写新状态；但阻塞中的 HTTPS 只能等待 15 秒读超时返回。

BOOT 安全边界

GPIO0 仍是 ESP32-S3 启动 strap。3 秒延时只阻止应用层误触发；按住 BOOT 上电或复位仍可能进入 ROM 下载模式。

当前真实链路使用 Qwen Chat，不是 DeepSeek。真实云测试环境还启用了 insecure TLS，且串口会打印截断的转写/回答；这些都必须在产品启用前收口。

语音输出框架

当前输出路径有两条：音频自检 beep 和档位预录语音播报。

audio_self_test

文件：audio_self_test.h/cpp

入口：BikeMbAudioSelfTest_Init、BikeMbAudioSelfTest_Tick、BikeMbAudioSelfTest_PlayPageTone、BikeMbAudioSelfTest_ConsumeCommand

audio_prompts

文件：audio_prompts.h/cpp、audio_prompt_assets.h/cpp

入口：BikeMbAudioPrompts_Init、BikeMbAudioPrompts_PlayMode

PlayMode 只提交播放请求并立即返回；实际 I2S 写入由后台 task 执行。

函数/数据作用
initSpeakerCodec()配置 ES8311，I2C 地址 0x18。
promptTask(...)后台等待 xTaskNotify，收到最新档位请求后播放对应 PCM。
g_requestSerial播放请求版本号。连续切换档位时，新版本会让旧语音在下一个 chunk 前中断。
writePrompt(...)把 16 kHz mono PCM 复制成 stereo I2S frame 输出，并检查是否被新请求打断。
kBikeMbPromptEcoPcm“经济模式”的 PCM 数据。
kBikeMbPromptTrailPcm“越野模式”的 PCM 数据。
kBikeMbPromptBoostPcm“增强模式”的 PCM 数据。
播放时序：UI 点击档位后立即更新页面；HandleModeChanged 调用 BikeMbAudioPrompts_PlayMode；播放请求写入 g_requestedMode / g_requestSerial 后通过 xTaskNotify(..., eSetValueWithOverwrite) 唤醒后台 task。连续点击时旧语音会被新请求打断。
语音资产生成：运行 tools/generate-mode-prompts.ps1，默认读取 src/assets/audio/mode-prompts/eco.mp3、src/assets/audio/mode-prompts/trail.mp3、src/assets/audio/mode-prompts/boost.mp3，转成 16-bit mono PCM, 16000 Hz 后写入 audio_prompt_assets.cpp。默认固件不会带入大语音数组。

区域简要说明
Bootloader / Partition Table启动链路基础设施。通常不在应用逻辑中直接操作。
nvs适合保存少量持久化数据，例如用户设置、传感器校准、累计里程。
otadata保存 OTA 选择状态，让 bootloader 知道启动哪个 app 槽。
app0/app1两个应用槽。默认布局每个约 6.25MB，比较适合当前 UI + 音频资源验证。
spiffs文件系统区域。后续如果字体/图片不想编译进固件，可以放这里。
coredump保存崩溃信息，辅助排查死机、异常重启。

当前限制

这些是后续继续开发前需要明确的边界。

音频链路所有权

AudioSession 已统一 AI、Audio Self Test 和 Audio Prompts；Voice Commands 尚未迁移，继续保持编译期互斥。

语音命令能力

voice-direct-test 没有唤醒词，可能误识别；当前 Arduino ESP-SR 路径也还没有启用中文命令识别。

真实云仍是测试配置

真实链路已接入，但使用 Qwen Chat、insecure TLS，并会打印截断后的转写和回答；默认固件仍关闭 AI。

AI 页面暂时只读

dashboard 第二页已经显示网络、状态、提示、波形和状态环；取消、重试、停止动作尚未接到 Assistant 命令接口。

取消和 TTS 延迟

取消不能主动关闭阻塞 HTTPS；CosyVoice PCM 完整缓冲后再播放，PSRAM 峰值和首包延迟仍需优化。

音乐路径未实现

HTTPS MP3 解码器、Stream Player、Music Service 和未来点歌 resolver 仍属于目标架构。

ESP-IDF 尚未接入 AI

ESP-IDF Runtime/Event/Service 已存在，但 AI、Wi-Fi、音频和语音实验仍以 Arduino 路径为主。
